4 → 저장로컬 SQLite

종료 → 재실행 → 비밀번호 확인 → 잠금 해제 흐름을 합성 테스트로 확인한 기반이 있음. 웹/Android 연결, 실제 Secret 사용 승인은 아직.

MCP는 현재 “어떤 키를 어디에 연결했는지” 기록하는 RecordOnly 모델. 플러그인 실행이나 키 자동 수집 기능은 아니다. Google 로그인만으로 모든 외부 가입 사이트·키를 알아낼 수는 없다.

03

DB를 혼동하지 않기

현재 SQLite ≠ 미래 서버 PostgreSQL ≠ 웹용 IndexedDB

현재 · 로컬 SQLite 실제 테이블
vault_state금고 헤더 + 감싼 Root Key 정보
revisions암호문 레코드의 불변 버전
heads현재 버전 → revisions 참조
conflicts충돌 후보/관찰 버전 → revisions 참조

저장 방식의 정확한 의미

  • 레코드 내용을 암호화해서 BLOB으로 저장.
  • SQLite 파일 전체를 암호화하는 SQLCipher 구현은 아님.
  • 버전·크기·불투명 ID 등 일부 메타데이터는 관찰 가능.
  • 서버 PostgreSQL 스키마와 Android 저장 통합은 아직.
  • GitHub 소스 백업은 사용자 금고 백업/복원 기능과 다름.

일반 테스트 성공 ≠ 보안 승인. Windows Phase 0A는 과거 Inconclusive 판정 유지, 명시적 ignored gate 재실행 없음. 유효한 과거 DB 롤백 탐지와 복구·기기 폐기·백업 훈련도 남아 있음.

이번에 확인한 것

소스·스키마·기존 설계·검증 기록을 대조해 구현/실험/예정을 분리. 저장소 기준 상태를 문서화.

이번에 하지 않은 것

제품 코드 변경, 서버 실행, DB 생성, 실제 키 입력, 커밋/푸시, 공개 배포. 전체 보안 인증이나 라이브 서비스 검증도 아님.
