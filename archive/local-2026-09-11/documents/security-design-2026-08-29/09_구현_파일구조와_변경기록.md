## 5. 파일별 구현 목적

| 파일 | 무엇을 구현할 예정인가 | RED 관점 확인점 |
| --- | --- | --- |
| 새 VFS `lib.rs` | 안전한 opaque capability와 상태 전이 | raw handle/connection을 외부에서 꺼낼 수 없어야 함 |
| `ffi.rs` | 필요한 ABI만 작은 unsafe 경계로 선언 | 길이, 포인터, lifetime, SQLite ABI mismatch |
| `vfs.rs` | `xOpen/xRead/xWrite/xLock/xShm*` 연결 | pathname 재오픈이나 stock-VFS fallback이 없어야 함 |
| `file_family.rs` | main/WAL 실제 handle 계열 획득과 유지 | 외부 writer/mapping, ABA, same-size rewrite, absent WAL race |
| `shm.rs` | 외부 `-shm`을 신뢰하지 않는 private mapping | WAL lock/recovery/checkpoint 의미가 깨지지 않아야 함 |
| `preflight_query.rs` | 첫 read snapshot을 고정하고 메모리 DB로 bounded backup | 공격자가 A/B 혼합 snapshot을 만들지 못해야 함 |
| `preflight.rs` | 인증과 RO→RW 승격 재검사 | A 승인 뒤 B를 쓰는 승격 공격을 거부해야 함 |
| `schema.rs` | 신규/기존 DB writable open 정책 | 잘못된 비밀번호·future·corrupt 경로에서 쓰기 0 |
| `store.rs` | guard를 writable store가 닫힐 때까지 소유 | 중간 drop으로 외부 writer 창이 다시 열리지 않아야 함 |
| `error.rs` | `Busy`, `InvariantViolation`, `UnsupportedPlatform` 등 매핑 | 경로·비밀번호·암호문이 오류에 노출되지 않아야 함 |

## 10. 실제로 생성된 Phase 0A 파일 구조

아래 파일은 현재 저장소에 실제로 존재한다. 이 tree는 격리 primitive probe이며 미래 full VFS tree가 아니다.

```text

├── src/
│   ├── lib.rs                              # 공개 타입과 Windows probe 가능 여부
│   ├── error.rs                            # 경로·Secret 없는 오류 code와 OS code
│   ├── file_guard.rs                       # FILE_SHARE_READ actual-handle control/guard
│   ├── probe_protocol.rs                   # bounded READY/MUTATE/MUTATED/EXIT frame
│   ├── windows_mapping_probe.rs            # creator handle 종료 뒤에도 남는 writable view
│   └── bin/
│       └── vault-vfs-feasibility-child.rs  # 별도 hostile child process
└── tests/
    ├── platform_contract.rs                # manifest MSRV와 SQLite pin
    ├── actual_handle_feasibility.rs        # 명시적으로만 실행하는 hard gate
    └── support/
        └── mod.rs                          # pipe IPC와 20초 hang watchdog

docs/
└── verification/
    └── windows-actual-handle-vfs-feasibility.md # primitive 관찰과 전체 Inconclusive 증거
```

## 11. Phase 0A 코드 흐름

```text
합성 파일 DEMO_VALUE_ONLY_MAPPING_A 생성
  → mapping 전 control open/read 성공 후 guard drop
  → child가 writable mapping/view 생성
  → child가 creator File handle 종료
  → child READY frame
  → parent가 no-write/no-delete-share guard 획득 시도
      ├─ guard 성공: No-Go
      ├─ OS code 32: child 종료 후 post-control로 이동
      └─ 다른 오류/timeout/4551: Inconclusive
  → post-control open/read가 원래 마지막 A byte 확인
      ├─ 성공: Phase 0A primitive Go
      └─ 실패: Inconclusive
  → verdict와 모든 command exit code 기록
  → 이 단계에서는 기존 SQLite store에 연결하지 않음
```

최종 후보에서는 위 흐름의 중간 acquisition이 exact OS code 32로 거부돼 단일 primitive Go를 관찰했다. 그러나 mandatory ordinary suite가 library test 실행 전에 오류 4551로 종료됐으므로 전체 Phase 0A는 Inconclusive다.

| 파일 | 구현 내용 | RED 확인점 |
| --- | --- | --- |
| `Cargo.toml` | 격리 crate, pinned `rusqlite/windows-sys`, probe feature | 새 의존성·feature가 store로 새지 않는가 |
| `lib.rs` | 오류·guard·probe의 최소 공개 API | raw handle/connection이 외부에 노출되지 않는가 |
| `error.rs` | `SharingViolation/Io/Protocol/UnsupportedPlatform` | 오류에 path·Secret·fixture 원문이 들어가지 않는가 |
| `file_guard.rs` | 합성 path를 `FILE_SHARE_READ`로 여는 독립 guard | 기존 mapping 존재 구간만 정확히 차단되는가 |
| `probe_protocol.rs` | 최대 32-byte fixed frame | 무한 입력·임의 명령·sleep race가 없는가 |
| `windows_mapping_probe.rs` | `CreateFileMappingW/MapViewOfFile` 수명 owner | creator handle을 실제로 닫고 view만 남기는가 |
| child binary | mapping 생성과 mutate/exit state machine | OS 오류 code를 잃지 않고 parent와 결정적으로 동기화하는가 |
| `actual_handle_feasibility.rs` | pre-control → hostile → post-control | 우연한 sharing violation을 false-Go로 오인하지 않는가 |
| `support/mod.rs` | child spawn, pipe, `WaitForSingleObject` | timeout/WAIT_FAILED/exit code가 Inconclusive로 남는가 |
| verification 문서 | 환경·명령·integer exit·판정 기록 | bare PASS, 과장된 full-VFS 통과 표현이 없는가 |

## 13. 실제 코드가 연결되는 순서

```text
tests/actual_handle_feasibility.rs
  ├─ temp 합성 파일 A 생성
  ├─ file_guard.rs로 pre-control open/read/drop
  ├─ tests/support/mod.rs가 child binary 실행
  │    └─ child → windows_mapping_probe.rs
  │         ├─ exact 25-byte CreateFileMappingW
  │         ├─ exact 25-byte MapViewOfFile
  │         ├─ creator File drop
  │         └─ mapping object + view만 유지
  ├─ probe_protocol.rs의 READY frame 수신
  ├─ file_guard.rs로 hostile acquisition 시도
  │    ├─ OS 32 → EXIT → post-control: primitive Go branch
  │    ├─ guard success → MUTATE/MUTATED → No-Go branch
  │    └─ 다른 결과 → Inconclusive branch
  └─ docs/verification/windows-actual-handle-vfs-feasibility.md에 결과 기록
```

`file_guard.rs`가 path를 여는 것은 **이 합성 primitive probe 안에서만 허용된 실험 장치**다. eventual SQLite VFS에서 pathname fallback 또는 stock VFS fallback을 사용해도 된다는 허가가 아니다.
