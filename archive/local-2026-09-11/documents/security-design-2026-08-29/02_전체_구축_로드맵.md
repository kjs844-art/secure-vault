# KeyAtlas 전체 구축 로드맵

## 한 줄 제품 정의

KeyAtlas는 사용자가 여러 사이트의 계정, 비밀번호, API 키, Secret, MCP 연결처와 사용 관계를 **암호화해 정리·검색·복구**하는 개인 보안 금고다.

## 전체 구조

```text
Android / Web UI
        ↓
서비스 로그인 계층 (Google, passkey, session)
        ↓
금고 잠금 해제 계층 (master password, device key, recovery slots)
        ↓
로컬 암호화 코어 + 검증된 SQLite 경계
        ↓
암호문 sync API / PostgreSQL / backup
        ↓
결제·권한·운영·감사 계층
```

서비스 로그인은 “누가 서비스 계정의 주인인지” 확인한다. 금고 잠금 해제는 “암호문을 복호화할 키를 사용할 수 있는지” 확인한다. 두 계층을 하나로 합치면 Google 계정 탈취가 금고 복호화까지 곧바로 이어질 수 있으므로 분리한다.

## P0 — 실제 Secret 입력 전에 끝낼 것

### 1. SQLite actual file-set 경계

- Windows custom VFS 또는 동등한 actual-handle 경계
- main/WAL/SHM identity, role, size, share mode 결속
- open→first query 이전 fail-closed
- RO→RW promotion에서 동일 file-set epoch 재확인
- store lifetime 동안 guard 유지

### 2. 최신성·완전성

- 과거 DB/WAL 전체 rollback 탐지
- canonical head rollback 탐지
- record/revision omission 탐지
- authenticated manifest/checkpoint와 독립 anchor

### 3. 복구와 기기 보안

- recovery Key Slot
- hardware-backed Android Keystore
- BiometricPrompt 기반 기기 키 사용 승인
- 신뢰 기기 폐기, key epoch 회전
- 모든 복구 수단 분실과 분실 기기 훈련

### 4. 보안 출시 gate

- 독립 암호 설계 검토
- Windows native/VFS 검토
- 침투 테스트
- Secret 비노출 로그·crash·clipboard 검사
- backup/export 복구 훈련
- 사고 대응과 키 회전 절차

## P1 — 합성 데이터로 제품 흐름 만들기

- Android: 생성, 잠금, 검색, 복사, 자동 잠금, 복구 화면
- Web: 편의 클라이언트와 별도 origin/배포 경계
- 계정/서비스/프로젝트/환경/키 관계 지도
- 만료일·회전일·연결처 기록
- 암호문 sync API와 PostgreSQL
- passkey/OIDC, session, device 관리
- 충돌 보존과 사용자 선택 UX

이 단계에서도 실제 Secret은 넣지 않고 합성 fixture만 사용한다.

## P2 — 공개 베타 준비

- signed build와 안전한 업데이트
- 개인정보처리방침, 이용약관, 계정 삭제
- 보안 문의와 취약점 신고 창구
- 데이터 보존·백업·삭제 정책
- Android 스토어 심사 자료
- 제한된 보안 베타와 복구 훈련

## P3 — 수익화와 확장

- Free/Pro 저장 한도와 entitlement
- 결제 provider, webhook, reconciliation
- 환불·다운그레이드·구독 만료 정책
- iOS, 브라우저 자동입력, TOTP, 팀 공유
- MCP/플러그인의 제한된 Secret capability

결제 상태가 암호화 키 소유권을 바꾸면 안 된다. 구독이 끝나도 사용자가 자신의 암호문을 안전하게 내보내거나 복구할 권리는 유지해야 한다.

## 사용자가 나중에 결정·준비할 것

- 최종 서비스명, 상표, 도메인
- GitHub organization 여부
- Google/Apple 개발자 계정
- 클라우드 provider와 IAM
- 결제 사업자와 가격·환불 정책
- 사업자·세금·약관·개인정보 문서
- 독립 보안 감사 범위와 비용
- 실제 Secret gate 개방에 대한 최종 승인

## 현재 다음 한 단계

Windows custom VFS와 private snapshot을 결합한 설계를 승인한 뒤, 저장소에 정식 spec을 작성하고 독립 검토를 거쳐 구현 계획으로 전환한다.
