브라우저의 합성 mail 화면은 동의 후 고정 fixture를 검사한다. OAuth 동의가 아니며
계정 소유권·실제 가입 여부를 인증하지 않는다. 수동 ‘확인됨’도 검토 표시다.
개발 서버에서 외부 요청이 없다는 근거와 공개 hosting의 수집 없음은 별개다.

## T1 공개 안내에 사용할 문구 후보

다음은 운영 주체/문의처/hosting 검토 후 채택할 문구 초안이다. 빈칸을 채우기 전 공개하지 않는다.

> 이 화면은 가상 데이터로 KeyAtlas의 기능을 체험하는 예시입니다.
> 실제 Gmail·외부 AI·서비스 계정에 연결하지 않으며 실제 비밀번호·API 키를 입력하면 안 됩니다.
> 가입 흔적·혜택·계정 관계는 가상 예시이며 현재 실제 가입 여부나 사용 가능한 잔액의 증명이 아닙니다.
> 화면의 분류·필터는 임시 상태입니다. 합성 금고의 저장 버튼을 사용하면 가상 암호문이 이 브라우저에
> 저장되고, 백업 버튼은 사용자가 요청한 합성 파일을 기기에 저장합니다. 다른 기기로 자동 동기화되지 않습니다.
> 브라우저 저장은 백업이 아니며, 브라우저 데이터 삭제나 기기 분실 시 사라질 수 있습니다.
> 운영 주체: [미확정]. 문의처: [미확정]. 적용일: [출시 후보 확정 후 기재].

현재 화면 종류마다 수명이 다르다. C04의 분류는 refresh로 원래 fixture로 돌아가고,
C06의 후보는 취소/닫기/5분 만료로 화면에서 제거된다. 합성 금고의 암호문은 refresh 뒤에도
남는다. 모든 화면이 같은 저장·삭제 방식을 사용한다고 안내하지 않는다.
JavaScript reference 제거나 암호문 byte 보존을 메모리의 안전 삭제 증거로 표현하지 않는다.

## T2 목적을 먼저 나눌 것

두 합성 처리 경로는 입력·목적·권한·제한이 다르다.

| 목적 후보 | 현재 코드/입력 | 승인 전 남은 결정 |
| --- | --- | --- |
| 가입 흔적의 제한된 후보 탐색 | C06: 고정 `.invalid` domain·제목·수신 시각, body 없음, 최대 100 headers/90일/제목 UTF-8 512 bytes. 결과는 서비스·coarse signal·UTC 날짜·검토 표시만 | 실제 Gmail pagination·필드/권한·출처·범위/비완전성, 추가 개인정보의 최소 처리 및 보존 |
| 혜택 내용 분석 | benefits 서버의 합성 Gmail FULL 정규화/후보 검증. body/snippet의 일부 처리와 별도 분석 목적이 있음 | body 필요성, 필요한 최소 권한, 로컬/외부 분석 선택·수신자·국외 처리·비용·삭제 |

근거: [C06 계약](../../../contracts/local-v1/signup-mail-discovery-v1.md),
[메일 처리 계약](../../../apps/benefits-web/MAIL_CONTRACT.md),
[R5A 설계](../../handoff/mvp-20260927/PROVIDER_ADAPTER_PLAN.md).
C06 metadata-only scope 제안을 FULL body 분석 허가로 해석하지 않는다.
기존 mail runner는 `externalAnalysis: true` 목적을 요구한다. 로컬 처리만 하려고 실제 동의 없이
true를 채우거나 같은 동의 policy를 다른 목적에 재사용하지 않는다.

Gmail metadata scope에서 `q` 검색을 쓸 수 없다는 제약을 포함해 권한/조회 설계를 검토해야 한다.
조회 편의를 위해 broad scope로 자동 fallback하지 않는다. 현재 scope와 Google 정책은 제안이며,
2026-10-03 공식 문서 읽기는 네트워크 URLError로 **BLOCKED**였다. effective grant·Google 심사·
실제 API 호환성은 **NOT_RUN**이다. 초안에 scope 문자열이 있다는 사실은 OAuth 승인 증거가 아니다.

## T2 처리·보존·삭제 결정표

| 데이터 | 목적/처리 제안 | 보존·삭제·검토 조건 |
| --- | --- | --- |
| 서비스 로그인 식별자/session | 검증된 권한·사용자 전환·동의/철회 제어 | 계정 수명과 별도 session expiry. 다른 사용자의 body owner 주장을 권한으로 쓰지 않음 |
| Google OAuth grant/token | 승인된 mailbox 접근·갱신·철회에 한정 | server credential 경계·접근/회전·철회·provider 폐기 검토. JS/URL/로그/AI에 노출 금지 |
| mail 원문·header/body | 승인 목적의 bounded 임시 처리 | 원문 장기 보관을 기본값으로 채택하지 않음. memory/cache/queue/실패 dump의 수명·접근까지 결정 |
| 후보·최소 근거·검토 상태 | 사용자 검토, 출처/기준시각·unknown/0 보존 | 저장 전 별도 확인, 사용자 소유권·revision·중복·삭제의 원자 경계 검증 |
| provider/AI 수신 데이터 | 공급자·필드 allowlist·목적이 승인된 범위만 | 재학습/재사용·보존·국외 처리·재수탁 여부 확인. 미신뢰 메일 지시를 권한으로 해석하지 않음 |
| 보안/운영 기록 | 고정 오류 코드·request correlation·최소 상태 | raw mail·token·Secret·backup·사용자 입력 제외. 보존/접근·삭제 담당·민감 메타데이터 검토 |
| operation ID/fingerprint·삭제 fence | 중복 command 방지·불명확한 결과 확인·삭제 후 재유입 차단 | 현재 canonical SHA-256은 익명화/암호화가 아님. 최소 항목·접근·보존과 payload 삭제 후 replay fence의 수명은 별도 결정 |
| 운영 backup | 승인된 복구 목적과 최소 범위 | 실제 생성 전 보존·복원·삭제 전파·접근/암호화/키 담당 결정. 삭제 요청 시 대기 기간과 재유입 방지 검증 |

구체적 보존 기간·처리 주체·수탁/제공 관계·국내외 지역·문의처·삭제 완료 시간은 모두 **미확정**이다.
임의로 ‘즉시 전체 삭제’, ‘국내 저장 완료’, ‘Google 검증 완료’를 안내하지 않는다.
R3A의 실제 Secret/복구와 서비스 로그인·Google token을 같은 키·수명 주기로 취급하지 않는다.

연결 해제/삭제 후에는 신규 수집 차단 → grant 철회·token 폐기 → 진행 작업 무효화 →
승인된 저장/cache/queue/로그/backup 정책의 삭제·보존 예외 확인 순서를 설계한다.
timeout/abort가 이미 저장된 명령의 rollback이나 provider 철회 성공 증명은 아니다.
삭제/철회 실패·불명확한 응답·재시작·기존 backup 복원 후 재유입도 검증 대상이다.

[R5A 저장·철회·삭제 설계](../../handoff/mvp-20260927/R5A_TRANSACTION_AND_DELETION_DESIGN_2026-10-03.md)는
접근 만료, 논리 content 제거, 물리 정리, backup 만료와 외부 수신자의 삭제를 구분한다.
관찰한 provider 철회와 app DB commit은 하나의 분산 원자 작업으로 보장되지 않는다.
이 초안으로 보존 기간·즉시 삭제·실제 provider 철회 완료를 확정하지 않는다.

## 초대 베타의 안내·동의 구성 제안

1. 실제 운영 주체·연락처·적용일, 초대 범위와 아직 미완료인 기능을 명시한다.
2. 연결할 계정, 목적(가입 흔적/혜택 분석), 선택 필드·기간·조회 한도·수신자를 설명한다.
3. Google OAuth grant와 제품의 처리 목적 동의를 구분하고 선택/거부/철회 경로를 제공한다.
4. 현재 계정·session·동의 버전·정확한 preview를 확인한 뒤 처리한다. 다른 scope의 결과는 폐기한다.
5. 결과가 단서이며 현재 가입·잔액·소유권 증명이 아님을 설명하고 저장 전 명시적 검토를 받는다.
6. 열람·정정·삭제·연결 해제와 보존/삭제 예외를 실제 구현에 맞춰 안내한다.

합성 UI의 checkbox와 preview 성공이 법적 동의·Google 권한·운영 삭제 구현을 대신하지 않는다.
한국 개인정보 안내, 위수탁/제공/국외 이전 구분, 필요한 법률/정책 검토와 Google 요구사항은
운영 주체·공급자·데이터 흐름 확정 후 독립 검토한다. 원본 Lovable/DB는 재사용/변경하지 않는다.

## M06 후속 완료 기준

- 위 미확정 항목을 사용자 결정과 실제 설정 근거로 채운다. 비밀값이나 실제 메일 자료를 문서에 넣지 않는다.
- 공개 notice/목적별 동의/연결 해제·삭제 안내가 실제 코드·설정·처리 흐름과 맞는지 대조한다.
- hosting/logging/analytics·운영 문의의 수집과 지역·보존을 검증한다.
- source/설정/notice 버전을 exact 출시 SHA에 묶고 변경 시 재검토한다.
- 법률·Google·독립 보안 검토와 실환경 결과를 각각 구분한다. 현재 이 문서는 초안 완료만 의미한다.

다른 AI에게 실제 메시지를 보내거나 새 세션을 만들지 않았다. 실제 배정·환경·배포·게시 권한은
기존 사용자 보류를 따른다.
