## 목표와 허용 경로

다른 AI의 “완료” 보고를 코드·검사·PR·merge·배포로 나눠 주 담당이 통합하기 쉽게 정리한다.
보안 판정이나 배포 설정은 하지 않는다. M06의 도메인/DB 선택 문서를 다시 작성하지 않는다.

- 새 `docs/verification/mvp-integration/pr-ledger/**`

다른 문서/source/CI 변경, PR base 변경/댓글/승인/merge, 재실행/cancel, 타 작업 브랜치
갱신, 타 checkout의 fetch/checkout/reset/stash는 금지한다. GitHub 읽기 API와 선택한
본인 checkout의 비파괴 조회만 사용한다. 조회한 비밀 원문/로그는 문서에 복사하지 않는다.

## 조사 기준

- M02 #21, M03 #17, M04A #16, M05A #18, M06 #20, 통합 #19의 최신 SHA/base/state를 조회한다.
  조회 날짜와 링크를 기록하며 미확인 값은 UNKNOWN으로 쓴다.
- 배정표의 기존 snapshot을 참고하되 최신이라고 가정하지 않는다. PR 설명만 믿지 않고
  해당 SHA의 handoff/source/evidence를 확인한다.
- main 전체 diff의 선행 공통 변경과 담당 소유 변경을 구별한다. 필요하면 고정
  `34b43e1a5d2f1d81eb2f6456d657fd04ca57332f` 출발점과 compare한다.
  API 파일 목록의 pagination/truncation을 확인한다. 전체 브랜치를 일괄 merge하지 않는다.
- 산출물 있음 / 작성자 로컬 검사 기록 / 직접 재검사 / 해당 SHA CI / 통합 후 검사 /
  main merge / 실제 배포를 별도 열로 기록한다. 자신이 실행하지 않은 검사는 저자 보고로 표기한다.
- CI의 정확한 실패 단계와 skip을 구별한다. 메타데이터만으로 assertion 원인을 단정하지 않는다.
  상세 조사에 실제 credential 로그가 필요하면 멈추고 민감정보 없는 근거를 요청한다.
- 충돌 가능한 파일, 선행 조건, 최저 위험 통합 순서와 미검증 항목을 짧게 제안한다.
  M06이 아직 예약 문서뿐이면 완료로 바꾸지 않고 현재 사실 그대로 표시한다.
- 사용자 선택/환경 보류 때문에 멈춘 항목과 코드 작업이 남은 항목을 나눈다.
