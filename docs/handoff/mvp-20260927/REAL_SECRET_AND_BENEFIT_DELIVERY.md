## 2. 먼저 전달할 혜택 이력의 범위

주 담당은 `apps/benefits-web/src/lib/demo-benefit-history.ts`와 관련 데모 화면을 맡는다.
이 문서 작성 시점에는 구현 중이며, 아래 기준의 검사 결과가 있어야 별도로 완료를 판단한다.

- 현재 확인할 기록과 과거 기록을 분리하되 원래 혜택을 자동 삭제하지 않는다.
- 만료 시각 또는 체험 종료 기록은 **기록상 과거 상태**다. 실제 계정 해지, 사용 완료,
  재가입, 현재 잔액을 추정하지 않는다. 과거의 남은 양을 지금 쓸 수 있는 양으로 합산하지 않는다.
- 지급·관찰·만료 시각과 메일/수동 등 출처를 유지한다. 날짜 불명은 불명으로 남기며,
  `null`을 0이나 사용 완료로 바꾸지 않는다. 출처가 메일이어도 현재 계정 상태의 증명은 아니다.
- 동일한 명시적 기준시각을 SSR과 브라우저가 사용하고, 만료 경계·Asia/Seoul 표시·빈 이력·
  충돌하는 서비스/혜택 종료일을 검사한다. 서비스 체험 종료를 무관한 크레딧에 적용하지 않는다.
- 합성 화면의 보기 전환은 실제 저장·메일 수집·계정 연결 기능이 아니다.
  실제 데이터 이력의 저장·보존·삭제 정책과 DB 검증은 승인 후 별도다.

## 4. R3A에서 빠뜨리면 안 되는 실제 비밀값 계약

1. **입력부터 저장까지:** 실제 사용자용 생성/unlock, 암호화 전 입력 검증, 키 소유자와
   전달 경계, 암호문 저장의 commit·재조회·재시작 복구를 함께 설계한다. 기존 합성 demo
   비밀번호를 사용자 비밀번호로 간주하거나 raw-key getter를 추가하지 않는다.
2. **계정 인증과 금고 재인증:** 서비스 로그인 성공은 Vault Root Key 해제 증명이 아니다.
   다시 보기/복사에 필요한 인증 수단과 최신성 정책을 먼저 정한다. 권한은 정확한 사용자·금고·
   세션 세대·키 epoch·항목 revision·행위·만료에 결합하고, 잠금/계정 전환/권한 철회 뒤 재사용을
   거부한다. 가짜 성공 boolean이나 오래된 UI 상태로 허용하지 않는다.
3. **보기 수명:** 명시적 사용자 동작으로 필요한 항목만 잠깐 표시한다. 숫자 TTL과
   재인증 재사용 범위는 검토 대상으로 남긴다. 잠금·만료·탭 숨김·페이지 이탈·세션 변경 시
   DOM/state와 소유 참조를 정리하고 이전 비동기 결과를 폐기한다. Rust zeroization이 JS 문자열,
   화면 캡처, 개발자 도구, 외부 복사본까지 지운다고 주장하지 않는다.
4. **복사 수명과 한계:** 명시적 복사 동작 시 현재 권한을 다시 검사하고, 거절/취소/지원 불가를
   고정 오류로 처리한다. clipboard에는 OS 기록·동기화·관리 앱·다른 앱이 접근하거나 사본을
   남길 수 있다. 자동 비우기 시도를 하더라도 브라우저 권한·활성 탭·타이머에 따라 실패할 수
   있고 이미 만들어진 사본은 회수하지 못한다. **안전한 자동 삭제를 보장하지 않는다.**
   사용자에게 잔여 위험을 알리고, 비동기 clipboard 쓰기 뒤 잠겼다고 외부 값도 회수됐다고 말하지 않는다.
5. **금지 경로와 회귀:** 비밀값을 URL, 로그, analytics, AI/MCP, 서버 평문, 오류 문자열에 넣지 않는다.
   잘못된/취소된 재인증, 동시 요청, 만료·잠금 직전/직후, 늦은 성공·실패, 다른 항목/세션으로의
   권한 재사용, 실패한 저장과 불명확한 commit, rollback·복구·키 폐기를 합성 E2E로 검사한다.
   실제 브라우저/플랫폼에서 관찰해야 하는 clipboard·포커스·수명 동작은 mock 통과와 분리해 기록한다.

현재 복구·키 폐기·동기화·rollback/누락 anchor·별도 금고 origin·공급망 보호와 독립 검토의
출시 조건은 유지한다. 보호 수단을 잃었을 때의 복구 한계와 복구 훈련도 필요하다.
웹의 Worker/WASM만으로 같은 origin의 악성 JavaScript를 격리한다는 보장은 하지 않는다.

## 5. 공수 범위와 완료 판정

아래는 현재 확인한 재사용 코드와 누락 경계를 바탕으로 한 **엔지니어 작업량 추정**이다.
견적 확정이나 달력상의 납기 약속이 아니며, 승인·독립 검토·인프라 대기 시간은 별도다.

| 범위 | 초기 공수 추정 | 전제·제외 |
| --- | --- | --- |
| 혜택 이력의 합성 화면·순수 분류·회귀 | **0.5~2 엔지니어일** | 기존 4서비스/6혜택 데모와 명시적 기준시각을 재사용하는 작은 변경. 실제 이력 DB, 메일 동기화, 현재 계정 검증은 제외한다. 충돌하는 상태 정책이 늘면 재산정한다. |
| 실제 비밀값 지원을 목표로 한 제한된 안전 코어 프로토타입 | **1~3+ 엔지니어주** | 설계·구현 승인을 받은 좁은 로컬 E2E를 합성 데이터로 검증하는 초기 범위. 실제 입력 API, 재인증 행위 결합, bridge 노출 수명과 clipboard 실패 경계가 새로 필요하다. 복구/기기/동기화 전체 제품 및 출시 승인까지의 기간이 아니다. |
| 실제 비밀값 출시 | **현재 확정 불가** | ADR 승인, 복구·키 폐기·rollback 대응, 플랫폼/브라우저 증거, 독립 암호·보안 검토 및 허용된 운영환경 상태가 미확정이다. 위 프로토타입 공수에 포함시키지 않는다. |

`코드 작성 → 합성 회귀 → 실제 실행 증거 → 독립 검토 → 출시 허용`은 다른 단계다.
이번 문서에서 어떤 단계도 새로 통과시킨 것으로 표시하지 않는다. 현재 Windows의 새 WASM
생성 정책 차단을 우회하지 않고, 필요한 브라우저 검사는 준비되지 않았다면 BLOCKED/NOT_RUN으로 남긴다.
이전 M01A/1A/2A의 최신 CI 성공과 이번 미커밋 변경의 검증은 별개다. 이번 작업에서는
CI 재실행·과금 변경·게이트 완화를 하지 않으며, 기존 성공을 새 변경의 CI 결과로 재사용하지 않는다.

## 6. 다른 AI에게 복사할 짧은 지시문

```text
KeyAtlas에서 REAL_SECRET_AND_BENEFIT_DELIVERY.md의 [R번호] 한 업무만 맡아 주세요.
먼저 AGENTS.md, 이 문서, 기존 M01A_DELEGATION.md와 해당 계약을 읽으세요.
주 담당에게 정확한 checkout/branch/허용 파일 목록을 확인받고 다른 변경은 보존하세요.
REAL_SECRET_GATE=CLOSED입니다. 실제 비밀값·메일·DB·외부 API 없이 합성 데이터만 사용하세요.
코어/인증/설정/DB/프로토콜 변경과 provider 연결은 해당 별도 승인 전 금지입니다.
소유 경로 밖 수정은 제안만 하세요. 새 설치, 보안 정책 우회, CI 실행, push/PR/merge는 하지 마세요.
완료 보고에 변경 파일, 정확한 검사 명령·exit, PASS와 NOT_RUN/BLOCKED, 남은 의존성을 적으세요.
합성 UI·mock 통과를 실제 인증·안전한 clipboard 삭제·실제 비밀값 출시 완료라고 말하지 마세요.
```

이번 인계의 산출물은 이 문서 한 개다. 읽기 검토와 로컬 문서 링크 확인 외 앱/코어 테스트,
브라우저·네트워크·CI·실환경 검증은 이 문서 작성 작업에서 실행하지 않는다.
