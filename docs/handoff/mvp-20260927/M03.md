## 검증

apps/web에서 npm test -- src/features/mvp-connections, npm run typecheck, npm run build. WASM 미생성이 다른 기존 suite를 막으면 관련 테스트 PASS와 전체 미검증을 구분한다. 네트워크 호출 없는 순수 함수 테스트를 우선한다.

단일 테스트 통과는 기능 전체 통과가 아니다. 검사에는 명령, exit code, 대상 SHA,
데이터 범위와 실행 환경을 함께 기록한다. 테스트용 비밀 문자열도 명백한 합성값만 사용한다.

한 AI는 한 브랜치와 한 작업 폴더만 사용한다. 공유 기존 파일 수정이 필요하면
이유와 최소 diff를 주 담당에게 보내 통합을 맡긴다. 예약 브랜치 개수는 진척률이 아니다.

## 복사해서 다른 AI에게 전달할 프롬프트

> M03.md에 따라 두 제품의 비밀 원문 없는 연결 참조 타입·검증기·합성 테스트를 독립 경로에 구현하라. 기존 Identity 코드를 읽고 중복 개념을 설명하되 기존 구현을 수정하거나 UI에 꽂지 말라.
> 저장소와 지정 브랜치를 확인하고, git status --short --branch / git rev-parse HEAD /
> git remote -v 결과를 먼저 확인하라. 새 장치는 이 지정 브랜치를 clone하고,
> 이미 존재하는 작업 폴더에서는 다른 사람의 변경을 보존하라. 허용 경로 밖의 코드는
> 수정하지 말라. 마지막에 변경 파일, 최종 SHA, 검사 명령/exit, 미검증 항목을 보고하라.
> 작업 완료는 리뷰 가능 상태를 뜻하며 main 병합이나 공개 배포를 수행하라는 지시가 아니다.
