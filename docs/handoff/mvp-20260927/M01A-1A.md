## 구현 기준

먼저 [HTTP 계약](../../../apps/benefits-web/HTTP_CONTRACT.md),
[카탈로그 계약](../../../apps/benefits-web/CATALOG_CONTRACT.md), 해당 source/test를 읽는다.

- 실제 global fetch를 기본으로 연결하지 말고 작은 transport 함수를 주입한다.
  source 경계 검사도 유지한다. 합성 transport/Fetch response로만 테스트한다.
- 같은 origin의 정확한 POST 경로와 고정 요청 헤더, same-origin credentials,
  redirect 거부, 명확한 timeout/AbortSignal 규칙을 만든다. 임의 외부 URL/헤더 입력 금지.
  Cookie/Origin 헤더를 JS에서 직접 만들지 않는다. 브라우저와 서버 세션이 담당한다.
- 요청 scope는 시작할 때 캡처한다. 로그아웃/계정 전환 후 지연 응답을 버리고
  이전 사용자의 데이터를 다음 scope로 넣지 않는다. scope를 서버 권한 필드로 보내지 않는다.
- CatalogView/Receipt/Page 및 고정 오류를 unknown부터 검증한다. 타입 단언만으로 신뢰하지 않는다.
  필드·종류·상한·revision·generation·날짜/null·deleted profile·user-reported provenance를 보존한다.
  서버 모듈의 runtime import 없이 동작해야 한다.
- 응답 본문도 실제 바이트/시간 상한을 두고 읽는다. 무제한 response.json/text 사용 금지.
- 자동 mutation 재시도 금지. 오류/timeout은 저장 취소 증거가 아니다. 수동 재시도는
  같은 scope에서 동일 command/operationId를 유지한다. 새 ID로 중복 저장하지 않는다.
- private metadata를 localStorage/sessionStorage/URL/로그/analytics에 넣지 않는다.
  새 crypto, 실키 저장, 로그인·결제·요금제·UI 디자인 구현은 범위 밖이다.
