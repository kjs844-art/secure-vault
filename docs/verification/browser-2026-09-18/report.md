## 확인한 동작

1. 격리된 페이지에서 `합성 금고 만들기`를 누르자 처리 중 상태를 거쳐
   `열림 · 저장된 암호문에서 3개 합성 항목을 인증하고 복원했습니다.`가 표시되었다.
   0/1/3개 연결을 가진 예시 1/2/3과 교체 완료 공간 예약 안내를 확인했다.
2. 예시 3을 선택하고 Example MCP만 `사용자가 확인했다고 가정`으로 바꾼 뒤
   `진행만 암호화 저장`을 눌렀다. 다시 인증된 목록은 3개 그대로였으며
   예시 3의 기존 3개 연결도 유지되었다. 저장 뒤 선택 UI는 예시 1로 초기화되었다.
3. 이때 IndexedDB를 읽기 전용으로 관찰했다. 데이터베이스는
   `keyatlas-synthetic-vault-v1`, store는 `bundle`, 저장값은 Uint8Array 5,160 bytes였다.
   암호문 SHA-256은 `ae098565ab5f2fdedd75f3983e2eb79f1911a093405d8d2b89297b818313c0ee`였다.
   원문 내용은 출력하지 않았다. 이 해시는 이 실행에서 생성된 합성 암호문의 동일성 비교용이다.
4. 잠금 버튼을 누르자 목록·교체·등록 영역이 사라졌다. 페이지를 새로고침한 뒤에도
   잠금 상태로 시작했다.
5. 재열기 → 예시 3 선택 → `저장한 진행 불러오기 · 검토`에서 MCP의 사용자 확인만
   복원되고 CLI/CI/폐기는 미확인 상태였다. `저장된 진행에 미확인 조건이 남아 있습니다.`가
   표시되고 최종 확정 checkbox/button은 비활성 상태였다. 이 전체 읽기 흐름 뒤
   저장 bytes와 SHA-256이 3번의 값과 정확히 같았다.
6. 모바일 viewport 360×800을 설정한 뒤 온라인으로 다시 열었다. 화면의 viewport,
   clientWidth, scrollWidth가 모두 360이었다. 상단 경고와 잠금 버튼을 inline screenshot으로
   관찰했으며 3개 목록이 다시 인증됐다. 실제 휴대폰/터치/생체인증 검증은 아니다.
7. 모바일/기본 viewport 전환과 Offline을 함께 설정한 두 시도에서는 브라우저가
   페이지를 다시 로드해 Chrome 오프라인 화면이 되었다. 해당 시도는 앱 내부 저장을
   실행하지 못했으므로 오프라인 저장 성공/실패 증거로 사용하지 않는다.
8. 온라인 기본 viewport에서 금고를 연 뒤 viewport를 바꾸지 않고 Offline으로
   전환했다. `navigator.onLine=false`, 기존 앱 title/목록은 유지됐다. 진행 불러오기와
   후속 저장 시도는 `BRIDGE_FAILURE`로 끝났고 Worker script 요청이 `net::ERR_ABORTED`였다.
   암호문은 5,160 bytes/3번 SHA 그대로였다. 온라인 복구 뒤 재열기로 3개 항목을 인증했다.
9. 재현을 단순화해 온라인 재열기 → Offline → 잠금 → 저장된 금고 열기를 수행했다.
   다시 같은 오류와 Worker script `net::ERR_ABORTED`를 관찰했다. 오류 화면은 inline
   screenshot으로 확인했다. 전체 오프라인 기능이 제공된다고 주장하지 않는다.
10. 테스트 소유 페이지 3의 네트워크 emulation을 복구하고 닫았다. 이번 preview
    session 56551을 `q`+Enter로 정상 종료(exit 0)했다. 기존 페이지 1/2와 다른 앱은 유지했다.

### 증거 방식과 도구 한계

Chrome DevTools 접근성 snapshot과 네트워크/콘솔, 읽기 전용 저장소 메타데이터를
사용했다. 잠금 화면 전체 screenshot은 대화 안에서 확인했다. 지정 경로 screenshot
저장은 도구의 workspace-root 정책에 의해 거부되었으므로 이미지 파일/영상이
저장됐다고 주장하지 않는다. 이 문제는 앱 오류가 아니라 도구 출력 경계다.
경로 제한 우회나 사용자 브라우저/프로필 삭제는 하지 않았다.

## 발견 사항

### ISSUE-001: 오프라인 Worker 시작 실패에 필요한 복구 안내가 없음

| 항목 | 값 |
| --- | --- |
| 심각도 | Medium — 안내/현재 지원 범위; 데이터 손실이나 암호화 우회 증거가 아님 |
| 분류 | UX / 기능 제한 |
| 재현 | 온라인 금고 열기 → Offline 전환(화면 크기 유지) → 잠금 → 저장된 금고 열기 |
| 기대 | 실행 환경/연결 확인, 암호문 보존, 사용자 주도 재열기를 이해할 수 있는 안내 |
| 실제 | 일반 `BRIDGE_FAILURE`와 재열기 안내만 표시. Worker JS 요청은 `net::ERR_ABORTED` |
| 우회 | 연결/로컬 서버를 복구한 후 사용자가 저장된 금고를 다시 열기 |
| 영상/파일 screenshot | 도구 제약으로 미수집; inline screenshot·snapshot·network 증거만 있음 |

네트워크에서 관찰한 JS 경로는 `assets/syntheticVault.worker-xgZH6uuT.js`다.
첫 시도의 Worker 요청 reqid 45/46, 단순 재현의 reqid 49가 중단되었다.
reqid 47/48은 중간 온라인 복구의 Worker/WASM 304 응답이었다.
첫 실패 후 보존된 bytes/hash 비교와 온라인 인증 성공을 확인했지만, 이것을 모든
실패 시점의 무쓰기 보장이나 플랫폼 전체 오프라인 지원 증거로 확대하지 않는다.

후속 수정은 `LocalVaultPanel`의 BRIDGE_FAILURE 안내에 한정한다. 원인을 네트워크로
단정하지 않고 Worker 실행/통신 가능성과 연결/로컬 서버 확인, 데이터 삭제·초기화
금지를 설명한다. 이 수정은 오프라인 기능 구현이 아니며 아래 기준 소스의
브라우저 관찰을 수정 후 실기 검증으로 대체하지 않는다.

초기 로드에서 `/favicon.ico` 404 한 건을 관찰했지만 강제 새로고침에서는 해당
요청 자체가 다시 발생하지 않았다. 재현 조건이 아직 확정되지 않아 발견 수에는
넣지 않았다. 금고 생성 후에는 콘솔 error/warn이 없었다.

### 수정 후 새 빌드의 제한된 재검증

같은 날짜 `codex/firstvibe-credential-commands` 작업 트리에서 default/demo WASM을
다시 생성하고 웹 production build를 실행했다. 새 테스트 페이지 4에서 실제 요청은
`index-BrFGGV3E.js`, `syntheticVault.worker-gQXDo1OW.js`,
`vault_client_wasm_bg-BzYvQGSt.wasm`이었고 각각 200이었다. 앞선 기준 빌드와 구분한다.

기존 격리 공간의 3개 항목을 온라인으로 다시 인증한 다음 Offline → 잠금 → 재열기를
수행했다. 새 Worker 요청 reqid 6은 `net::ERR_ABORTED`, 상태는 BRIDGE_FAILURE였으며
새 안내가 실제 DOM에 표시됐다. 원인 미확정, Worker 시작/통신 가능성, 연결·로컬 서버
확인, 복구 후 수동 재열기, 데이터 삭제/초기화 금지가 모두 포함됐다.
이후 5,160 bytes/기존 SHA가 유지됐고 온라인 복구 뒤 3개 항목 재인증도 성공했다.

따라서 ISSUE-001의 **누락된 안내는 보완·실기 재검증했다**. 오프라인 기능 제한 자체는
남아 있다. 이 재검증도 DOM/network 증거이며 영상/스크린샷 파일은 없다.
테스트 페이지 4를 닫고 preview session 94130을 정상 종료(exit 0)했다. 다른 페이지나
사용자 앱은 종료하지 않았다.

## 미검증 범위

다중 writer 충돌/폐기, 네이티브 파일 다운로드·선택, ready 진행의 재개/동의/최종 확정,
유휴 5분·탭 숨김·실제 모바일 생명주기는 이번 실행에서 끝내지 않았다. 이전 실행의
증거와 이 실행을 구분한다. 실제 Secret, 사용자 로그인/복구, 공급자 API, 공개 배포,
실제 모바일 하드웨어, 클라우드 동기화는 범위 밖이다. 수정 후 검증은 위 오류 안내·보존·
온라인 재열기로 한정되며 전체 실기 회귀와 완전한 오프라인 지원은 별도 남은 작업이다.
