## M05A: 현재 gate로 채택할 수 없는 이유

근거 스크립트:
[제출 SHA의 local-vault-qa.mjs](https://github.com/kjs844-art/secure-vault/blob/e6e5700d5931a1ce37f93f83049e5cc145e46021/apps/web/tests/mvp-browser/local-vault-qa.mjs).
이번에는 이 스크립트를 실행하거나 현재 브랜치에 복사하지 않았다.

1. **실패 종료가 보장되지 않는다.** 각 scenario는 FAIL을 기록해도 종료 코드를
   바꾸지 않는다. 출력 쓰기와 종료가 성공하면 검사 실패가 있어도 exit 0이 가능하다.
   실패/누락/BLOCKED를 비정상 종료로 연결하고, cleanup을 finally로 보장해야 한다.
2. **잠금·재열기 근거가 좁다.** `.first()` 선택자는 생성 버튼도 허용한다. 복원 검사는
   명시적인 열기 버튼과 정확한 archive 키의 유효한 크기/전체 해시 비교가 필요하다.
   잠금 검사는 한 문자열 부재/Tab 20회로 전체 민감 DOM 제거를 증명하지 못한다.
   검사 문구의 '최종 확인'은 실제 UI의 '최종 확정'과 다르다.
3. **DB 실패/범위 구분이 부족하다.** 이름에 keyatlas가 포함된 첫 DB를 선택하고,
   S5는 이를 삭제·재생성하며 delete의 error/blocked를 성공처럼 처리한다.
   write request 성공과 transaction commit도 구분하지 않는다. 정확한 합성 DB만
   쓰는 scenario별 새 context, strict failure 처리, transaction 완료 대기가 필요하다.

그 밖에 `QA_BASE_URL` 문서와 고정 BASE가 다르고 `/tmp` 출력 경로도 고정돼 있다.
Playwright는 현재 앱의 직접 의존성이 아니므로 실행 가능하다고 가정하거나 임의 설치하지 않는다.
보고서에는 검토 SHA, runtime/browser, 실행 시간, scenario별 필수 관찰값이 필요하다.
예외 본문·페이지 민감 내용은 그대로 결과에 출력하지 않는다.
