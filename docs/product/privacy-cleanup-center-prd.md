# KeyAtlas Privacy Cleanup Center — 제품 요구사항 초안

| 항목 | 값 |
|---|---|
| 작업 | `KA-PRI-P01` |
| 문서 상태 | **초안** — 독립 제품·보안 경계 검토와 사용자 승인 전 |
| 작성 기준 | 2026-09-25, `d9c66661db7d7b66f6453e94e467c424107cba66` 기반 작업 공간 |
| 실제 정보 경계 | `REAL_SECRET_GATE=CLOSED` — 합성 데이터만 사용 |

이 문서는 앞으로 만들 제품의 **요구사항**이지 구현·운영·법률 승인 증거가 아니다. 현재 Privacy Cleanup Center의 화면, 저장 계약, 외부 서비스 연결, 탈퇴·삭제 실행은 미구현이다. `KA-PRI-P01` 승인 전에는 후속 구현의 선행 조건이 충족된 것으로 보지 않는다.

## 1. 사용자가 얻을 결과

KeyAtlas는 사용자가 **자신이 가진 기록**을 바탕으로 가입한 서비스, 로그인 수단, 자격 증명과 사용처, 동의·구독, 정리 요청의 진행 상황을 한곳에서 확인하도록 돕는다. 정리의 핵심은 “무엇을 요청했고, 어떤 근거로, 어디까지 처리됐으며, 언제 다시 확인할지”를 놓치지 않는 것이다.

제품 문구는 “계정과 연결을 정리하도록 돕는다”, “출처별 후보를 모아 확인한다”, “공식 절차를 안내하고 요청 상태를 기록한다”로 한정한다. 다음은 약속하지 않는다.

- 이메일 주소·전화번호·소셜 로그인만으로 **모든 가입 사이트를 자동 발견**한다.
- 한 번의 클릭으로 모든 서비스의 동의·연결·계정·게시물·개인정보를 **자동 삭제**한다.
- 제공자가 가린 과거 API 키의 원문을 복원한다. 원문은 최초 발급 때 사용자가 안전하게 저장한 경우에만 다시 볼 수 있다는 별도 금고 조건을 따른다.
- 접수증이나 검색 제외만으로 원본 데이터 삭제, 계정 탈퇴 또는 법적 의무 이행을 보장한다.

## 2. 범위와 단계

| 단계 | 포함 | 제외 또는 별도 승인 |
|---|---|---|
| `P01` 현재 | 용어, 사용자 여정, 안전 경계, 합성 수용 기준 정의 | 코드·화면·외부 호출·실제 개인정보 처리 |
| `P02–P06` 후속 후보 | 합성 Identity/Consent/Cleanup 계약, 암호화 로컬 저장 설계, UI, 승인 상태기계, 공식 경로 카탈로그 | 실제 계정 수집·OAuth 동의·요청 전송·키 폐기 |
| `P07+` 별도 게이트 | 제공자별 제한된 보조·연결·사건 추적을 검토 | 사용자 동의, 제공자 정책, 개인정보·법률·보안 검토 없이 실행 불가 |
| 미래 `Privacy Care` | 사람이 돕는 서비스의 가능성 검토 | 적법한 위임·최소 접근·운영 체계·전문가 검토 전 판매·대행 불가 |

공개 서비스, 제한된 실제-Secret/Privacy beta, 유료 지원의 출시 판단은 이 PRD 밖의 별도 게이트다. 문서 작성만으로 `REAL_SECRET_GATE`를 열지 않는다.

## 3. 정보 관계와 용어

`IdentityProfile → ServiceAccount → LoginMethod / Credential → Connection / ConsentGrant / Subscription / EvidenceSource → CleanupCase → CleanupAction + 상태 이력 + 다음 확인일`을 개념 관계로 사용한다. 이는 구현 스키마가 아니라 사용자가 이해할 정보 구조다.

| 용어 | 뜻과 구분 |
|---|---|
| `ServiceAccount` | 사용자가 특정 서비스에 가진 것으로 기록하거나 확인한 계정. 발견 후보와 확인된 계정을 구분한다. |
| `LoginMethod` | 이메일, 패스키, 제공자 로그인 등 로그인 방식. 제공자 로그인이 다른 사이트의 계정 목록을 뜻하지 않는다. |
| `Credential / Connection` | 자격 증명과 그 사용처(앱·MCP·CLI·CI·서버 등). 원문 접근 가능성은 별도 금고 상태에 달린다. |
| `ConsentGrant` | 마케팅, 제3자 제공, OAuth 범위, 알림, 약관 버전 등의 기록. 사용자가 기록한 값과 제공자에서 현재 확인된 값을 구분한다. |
| `Subscription` | 해당 **외부 서비스**의 무료·유료·체험·갱신·해지 기록. KeyAtlas 자체 결제와 혼동하지 않는다. |
| `EvidenceSource` | 정보의 출처·관찰 시각·확인 시각·확인 방법·신뢰 수준. 출처 없는 추정을 사실로 승격하지 않는다. |
| `CleanupCase / CleanupAction` | 정리할 대상·요청 유형·사용자 승인·접수·결과·재확인을 각각 남기는 사건과 행위. |

## 4. 여섯 가지 사용자 여정

1. **가입·연결 기록:** 사용자가 합성 서비스 `EXAMPLE_SERVICE`의 계정 별칭, 로그인 방식, 자격 증명 별칭 `EXAMPLE_KEY_A`, 사용처 `EXAMPLE_CI`를 연결해 기록한다. 잠금 해제 뒤 Identity Map 시작 화면에서 발급처·키·사용처 관계를 최대 3번의 화면 이동/항목 선택으로 찾되, 저장하지 않은 원문은 보인다고 약속하지 않는다.
2. **동의·구독 기록:** 사용자가 동의 종류, 선택/필수 여부, 외부 구독 상태, 확인 날짜를 기록한다. 원문 동의 문서/공식 화면의 출처와 사용자의 메모가 별도 항목으로 보인다.
3. **정리 대상 발견:** 사용자 수동 입력, 사용자가 선택한 import, 가입 메일, 공식 연결 화면/API 중 허용된 출처에서 후보를 만든다. 출처와 확인일을 보여 주고, 추정 후보는 사용자의 확인 전까지 확정 계정으로 표시하지 않는다. 메일/import/공식 API 기능 자체는 후속 게이트 전 미구현이다.
4. **정리 사건 생성:** 사용자가 수신 거부, 동의 철회, OAuth 연결 해제, 키 교체·폐기, 구독 해지, 회원 탈퇴, 개인정보·게시물 원본 삭제 요청, 검색 제외/노출 억제 중 **하나의 결과 유형**을 고른다. 서로 다른 결과를 하나의 “삭제 완료”로 합치지 않는다.
5. **안전한 실행:** 제품은 검증된 공식 경로와 요청서 **초안**을 보여 준다. 기본 흐름은 사용자가 제공자 화면에서 최종 전송/클릭을 직접 하는 것이다. 그 전에 금고 잠금 해제와 별도의 재인증·대상·영향·복구 가능성 확인을 요구한다. 합성 단계에서는 어떤 외부 요청도 보내지 않는다.
6. **처리 추적과 재확인:** 사용자는 초안, 사용자 전송, 접수 불확실, 제공자 접수, 추가 인증, 일부 처리, 거절, 범위가 명시된 완료 통지, 확인 불가, 재노출을 구분해 기록하고 다음 확인일을 정한다. 접수 증거만 있으면 “접수”로 남으며 자동으로 “완료”가 되지 않는다.

## 5. 출처·증거·결과 상태

### 5.1 발견 출처

모든 후보에는 출처 라벨, 수집/관찰 시각, 마지막 확인일, 접근 범위, 사용자 수정 가능성을 붙인다.

| 라벨 | 표시할 사실 | 표시하면 안 되는 결론 |
|---|---|---|
| `사용자 입력` | 사용자가 직접 기록함 | 제공자가 현재 계정 보유를 확인함 |
| `사용자 선택 import` | 특정 파일/내보내기에서 발견됨 | 사용자의 모든 계정을 포괄함 |
| `가입 메일 후보` | 사용자가 허용한 메일 범위에서 관련 메시지를 발견함 | 계정이 현재 활성 상태임 |
| `공식 연결 화면/API` | 해당 제공자의 화면/API가 특정 시각에 보여 준 범위 | 다른 제공자까지 포괄하거나 이후 상태가 유지됨 |
| `추정 후보` | 규칙·정황상 확인할 필요가 있음 | 확인된 가입·동의·삭제 사실 |

출처가 없거나, 공식 링크가 깨졌거나, 제공자 절차가 바뀌었거나, 확인일이 오래된 경우 `UNKNOWN / 재확인 필요`로 낮춘다. “오래됨”은 출처/제공자별로 문서화된 최신성 기간을 넘었음을 뜻하며, 그 기간이나 확인일이 아직 설정되지 않았으면 기본값도 `UNKNOWN`이다. 여러 출처가 충돌하면 사용자에게 충돌을 보여 주며 한쪽을 조용히 덮어쓰지 않는다. 오탐은 사용자가 제거·정정할 수 있어야 한다.

### 5.2 사건의 진행과 결과

사건은 `발견 → 대상 확인 필요 → 요청 준비 → 재인증/승인 대기 → 사용자 전송 → 접수 확인 또는 접수 불확실 → 추가 인증/처리 대기 → 결과 기록 → 재확인`의 이력을 가진다. 취소, 실패, 거절, 일부 처리, 증거 없음, 확인 불가, 재노출은 별도 분기이며 이전 사건·증거를 지우지 않는다. 각 사건에는 대상, 행위 유형, 상태를 바꾼 주체, 시각, 근거, 다음 확인일을 남긴다.

| 표시 | 필요한 근거 | 금지할 자동 승격 |
|---|---|---|
| `초안` | 사용자가 아직 외부로 보내지 않은 내용 | 초안을 접수로 표시 |
| `사용자 전송` | 사용자의 전송 기록/진술과 그 출처 | 전송만으로 제공자 접수나 완료로 표시 |
| `접수 불확실` | 최종 클릭 후 시간 초과·응답 소실 등으로 접수 여부를 확인하지 못함 | 실패로 단정하거나 자동 재전송; 제공자 기록을 확인하기 전 재시도 유도 |
| `제공자 접수` | 제공자 접수 화면·번호·회신 등, 관찰 시각 | 접수만으로 처리 완료로 표시 |
| `일부 처리 / 거절 / 추가 인증` | 제공자 응답 또는 사용자 관찰과 그 범위 | 남은 항목을 완료로 표시 |
| `화면상 미노출` | 공식 목록 또는 검색 결과에서 보이지 않았던 화면·시각·범위 | 이 관찰만으로 원본 삭제나 계정 탈퇴 완료로 표시 |
| `제공자 완료 통지` | 해당 행위와 대상에 대한 제공자의 명시적 완료 통지, 시각·적용 범위 | 제공자의 주장 범위를 넘어 모든 사본 삭제·영구 미노출로 확대 |
| `확인 불가 / 증거 없음` | 검증할 수 없다는 명시 | 긍정적 완료로 표시 |

사용자 진술, 화면상 미노출, 제공자 완료 통지는 서로 다른 증거 등급이다. 명시적 완료 통지도 **제공자의 주장과 그 시각·범위**만 뜻하며, 영구 미노출이나 모든 복제본 삭제를 보장하지 않는다.

## 6. 파괴적 작업 승인 경계

`회원 탈퇴`, `계정 병합`, `API 키 폐기`, `연결 해제`, `유료 구독 취소`, `동의 철회/수신 거부 전송`, `법적 삭제 요청 전송`, `게시물 원본 삭제`, `검색 제외 신청`은 잠금 해제만으로 백그라운드 실행하지 않는다. 기본 UX에서 KeyAtlas는 공식 경로·양식 초안·체크리스트·알림·상태 분류까지만 돕고, 사용자가 제공자 화면에서 최종 전송/클릭을 직접 한다.

자동 제출 기능은 현재 기본 흐름이 아니며, 향후 사용자 별도 승인·제공자 정책·보안/개인정보/법률 검토를 통과한 제공자별 기능으로만 검토한다. 그 경우에도 각 행위 직전에 **대상 계정·제공자·영향 범위·되돌릴 수 있는지·예상 손실**을 다시 보여 주고 별도 재인증과 명시적 최종 승인을 받는다. KeyAtlas가 만드는 무단 전송과 응답 불명 상태의 자동 재시도는 0이어야 한다. 네트워크 시간 초과 뒤 실제 접수 여부는 불확실할 수 있으므로, 제공자 기록을 확인하고 지원 시 요청 식별자를 대조하기 전에는 재전송하지 않는다. 멱등성 지원 여부는 제공자별로 확인해야 하며 **실제 중복 접수 0건을 보장하지 않는다**. 무단 스크래핑·무승인 자동 제출·rate-limit 우회는 후속 adapter의 범위에도 포함되지 않는다. 공식 절차가 불명확하거나 결과 확인이 실패하면 `UNKNOWN / 확인 필요`로 멈춘다. 타인 게시물, 명예훼손·불법 콘텐츠, 사망자 계정, 신분 증명, 법적 분쟁은 셀프서비스 자동 실행 대상이 아니며 적법한 주체와 전문가 판단이 필요하다.

## 7. 데이터 보호 요구와 비목표

- 요구: 금고 원문과 꼭 필요한 민감한 사건 증거는 클라이언트 측 암호화 대상이다. 기본 보관 증거는 공식 URL, 접수번호, 날짜, 상태처럼 사건 입증에 필요한 최소 항목으로 제한한다. 신분증 사본·메일 전체 본문·키 원문을 기본적으로 장기 보관하거나 운영자 검색용 평문 DB에 복제하지 않는다. 일시 분석 자료는 목적 달성 뒤 폐기하는 방향이며, 서버 동기화가 생긴다면 불투명 암호문과 승인된 최소 운영 메타데이터만 취급한다. 이는 **검증 전 설계 요구**이며 현재 구현 보증이 아니다.
- 요구: 잠금 상태에서는 사건 상세·증거·민감한 계정 관계를 읽을 수 없어야 한다. 알림에는 계정/자격 증명 이름이나 민감한 요청 내용을 넣지 않는다.
- 후속 설계 결정: 증거별 보존기간, 사용자의 내보내기·삭제 절차, 일시 분석 자료의 폐기 시점과 예외를 데이터 흐름/법률 검토에 맞춰 명시하고 합성 테스트로 검증한다. 아직 기간·정책은 정하지 않았다.
- 비목표: 범용 계정 검색 엔진, 모든 제공자의 통합 삭제 API, 제공자 정책 우회, 법률 대리, 자동적 신원 확인, **다른 사람이 소유한 계정**의 정리, 실제 키 원문 복구.
- 외부 법률·개인정보 검토 전에는 보존기간, 삭제 의무, 국가별 권리 행사 가능성을 제품 보장 문구로 쓰지 않는다.

## 8. 합성 사례 수용 기준 초안

아래는 **미실행** 수용 기준이다. `P01` 문서 검토와 후속 구현 테스트를 구분한다. 모든 사례는 합성 별칭만 사용하고 외부 요청·OAuth scope·실제 개인정보·실제 Secret을 사용하지 않는다.

| 사례 | 기대 관찰 결과 |
|---|---|
| 합성 계정–키–연결처 3개 기록 | 잠금 해제 후 Identity Map 시작 화면에서 발급처→키→세 연결처를 3번 이내의 화면 이동/항목 선택으로 찾음. 클릭/탭으로 화면·선택이 바뀔 때마다 1회로 세고, 잠금 해제·검색어 입력·스크롤은 제외; 저장하지 않은 원문은 노출하지 않음 |
| 사용자 입력·import·메일 후보·공식 화면·추정 후보 혼합 | 각 카드에 출처와 확인일 표시; 추정/메일 후보는 확인된 활성 계정으로 보이지 않음 |
| 깨진 공식 URL, 확인일/최신성 기간 미설정, 또는 기간이 지난 화면 | 모두 `UNKNOWN / 재확인 필요`; 실행 버튼이나 완료 판정으로 조용히 진행하지 않음 |
| 잘못 발견된 합성 후보 | 사용자가 정정·제외할 수 있고 다른 확인 계정/사건은 변경되지 않음 |
| 합성 요청 증거 등록 | 기본 필드는 공식 URL·접수번호·날짜·상태 같은 최소 항목; 신분증 사본·메일 전체 본문을 기본 장기 보관하지 않음 |
| 잠금 상태 또는 승인 대기 상태에서 외부 변경 시도 | 민감 상세 조회 0, 외부 전송 0, 폐기·취소·연결 해제 0 |
| 동일 사건의 승인·전송 두 번 시도 | 기본 UX에서는 사용자의 최종 클릭 전 KeyAtlas 외부 전송 0건; 향후 자동 제출 설계는 별도 승인 없이는 비활성 |
| 합성 제출의 시간 초과·응답 소실 | `접수 불확실`로 남고 자동 재시도 0건; 제공자 확인 전 실패·완료 단정 없음. 후속 adapter는 지원 시 요청 식별자/멱등성 검증, 미지원 시 수동 확인 경로를 검증 |
| 접수증만 있는 삭제 요청 | `접수` 표시, `완료` 아님; 거절·일부 처리·추가 인증·확인 불가가 각기 별도 상태 |
| 탈퇴·원본 삭제·검색 제외를 각각 기록 | 서로 다른 사건/결과로 유지하고 하나의 “삭제 완료”로 합치지 않음 |
| 목록에서 사라졌지만 완료 통지는 없는 계정/게시물 | `화면상 미노출`만 기록; 원본 삭제·계정 탈퇴 완료로 승격하지 않음 |
| 제공자 완료 화면 뒤 재노출 관찰 | 이전 완료 근거와 새 재노출·재확인일을 모두 남기며 영구 삭제 보장 문구 없음 |

후속 구현의 검사에는 상태 전이·중복 방지·잠금/오류/빈 화면/대량 목록·접근성, 민감 정보 평문 유출, 승인 없는 외부 변경을 포함해야 한다. 이 PRD만으로 그 검사를 통과했다고 주장하지 않는다.

## 9. 사용자에게 남은 결정

다음 결정은 설계자가 임의로 확정하지 않는다.

1. 첫 출시 범위: 합성 로컬 셀프서비스에서 어떤 정리 행위와 어떤 제공자를 먼저 다룰지.
2. 가입 메일·import·OAuth 후보 탐색 허용 여부, 데이터 출처별 최소 권한과 보관/삭제 범위.
3. 기본값인 **사용자 최종 클릭** 외 자동 제출을 미래에 제안할지. 제안하더라도 별도의 사용자·제공자 정책·안전성 승인 전에는 범위에 넣지 않는다.
4. 서비스 국가·사업 주체·법률/개인정보 처리 범위, 사건 증거 보존기간·내보내기·삭제 요구와 지원 주체.
5. 타인·사망자·분쟁 사건 및 유료 사람 지원을 제품에서 제외할지, 별도 전문가·운영 체계로 다룰지.

`KA-PRI-P01` 종료 조건은 독립 제품·보안 경계 검토 결과와 위 사용자 결정/보류 사항을 기록한 뒤 사용자에게 초안 승인 여부를 확인하는 것이다. 그 전에는 작업판의 완료 체크를 하지 않고, 실제 외부 실행이나 beta 준비 완료로 표시하지 않는다.
